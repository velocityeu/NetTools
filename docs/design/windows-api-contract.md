# Windows API and runtime contract

Status: design review, 12 September 2026. No application code or compatibility testing has been performed. This contract supports the [product design](product-design.md) and [embedded help design](help-and-about.md); it does not authorise application development.

## Runtime and compatibility boundary

Target one portable x64 executable, built with C++20, MSVC and the Windows SDK. The minimum target is Windows 10 build 10240; Windows 11 and Windows Server 2016 or later with Desktop Experience are also in scope. Server Core is excluded. This is an application compatibility target, not a statement about Microsoft's servicing lifecycle.

Use the release static runtime (`/MT`) consistently across application code and linked libraries. This removes the application's dynamically linked MSVC runtime requirement; it does not remove Windows DLL dependencies or prove that a chosen compiler, standard-library feature or third-party library supports build 10240. Record the compiler/SDK versions and inspect the final executable's imports, including dependencies introduced by libraries. Embed the manifest, icon, manual, search index and notices. No executable-adjacent runtime DLLs or help files are required. [Microsoft runtime options](https://learn.microsoft.com/en-us/cpp/build/reference/md-mt-ld-use-run-time-library).

Only functions available on **every** target may be unconditional imports. Compilation against a recent SDK, a Windows version check after startup, and an `if` around a direct call do not make a missing imported function safe. Resolve optional functions by name from the appropriate system module and handle absence or failure. SDK declarations are not a compatibility test.

The minimum column describes the relevant desktop API or capability, not additional operating systems supported by this product. Ordinary User32/Kernel32/Gdi32 operations already present on the target remain valid; each new API introduced during development must meet the same review rule.

The stock **IP Address control is unsuitable** for the shared IPv4/IPv6 field: it contains four numeric octet fields. Use a normal edit control so IPv6 and a pasted CIDR fit the same interaction. The parser must define treatment of leading zeros, whitespace, scope IDs, ports and brackets without accepting unconsumed suffixes or triggering DNS. A scoped IPv6 endpoint is distinct from a prefix: do not silently make its zone identifier part of network arithmetic. [IP Address control](https://learn.microsoft.com/en-us/windows/win32/controls/ip-address-controls), [literal parsing](https://learn.microsoft.com/en-us/windows/win32/api/ws2tcpip/nf-ws2tcpip-inetptonw).

Rich Edit does not automatically supply the planned help browser, offline index, history, heading focus, accessible names, printing commands or reliable image descriptions. Those remain application responsibilities. The topic generator must constrain and verify Rich Edit's supported tables/images, retain textual explanations, escape content correctly, and disallow arbitrary external RTF/OLE objects. A styled heading alone is not evidence of screen-reader heading navigation. [Rich Edit capabilities](https://learn.microsoft.com/en-us/windows/win32/controls/about-rich-edit-controls).

## DPI compatibility contract

Use the manifest to establish process awareness before window creation: legacy `dpiAware` value `true/pm`, plus newer `dpiAwareness` preference list `PerMonitorV2, PerMonitor`. Windows versions before 1607 ignore the newer element. This preserves PMv1 for build 10240 while allowing PMv2 on capable versions. Do not redundantly call a process-awareness setter after the manifest has already established the mode. [Manifest behaviour](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process).

| Capability | Minimum | Required earlier-system path |
| --- | --- | --- |
| PMv1; `WM_DPICHANGED` | Windows 8.1 / Server 2012 R2 | Baseline. Store each window's DPI, apply the message's suggested rectangle, and rescale/reflow owned child controls and fonts. [WM_DPICHANGED](https://learn.microsoft.com/en-us/windows/win32/hidpi/wm-dpichanged). |
| `GetDpiForWindow` | Windows 10 1607 / Server 2016 | Optional function pointer. On 10240/1511 use the legacy PMv1 initial-monitor query described below, then track `WM_DPICHANGED`. [GetDpiForWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdpiforwindow). |
| `AdjustWindowRectExForDpi`, `GetSystemMetricsForDpi` | Windows 10 1607 / Server 2016 | Resolve independently. Earlier builds use baseline window sizing/system metrics with explicit client layout at the stored DPI. Do not blindly multiply every system metric or assume PMv2 non-client behaviour. [Window sizing](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-adjustwindowrectexfordpi), [metrics](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getsystemmetricsfordpi). |
| `EnableNonClientDpiScaling` | Windows 10 1607 / Server 2016 | Optional for PMv1 top-level windows, called in `WM_NCCREATE`. Skip when absent; preserve the older OS frame behaviour. PMv2 does this automatically. [Non-client scaling](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enablenonclientdpiscaling). |
| `SetThreadDpiAwarenessContext` | Windows 10 1607 / Server 2016 | Optional only if a future scoped thread override is necessary; not needed to select the default manifest mode. Restore a successfully returned previous context on the same thread. [Thread context](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setthreaddpiawarenesscontext). |
| PMv2 / `SetProcessDpiAwarenessContext` | PMv2 from Windows 10 1703; function reference lists 1703 client and Server 2016 | Use manifest negotiation; do not infer PMv2 from the Server product name. No unconditional import. If programmatic selection is ever substituted, resolve and check support before creating windows. [Process context](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setprocessdpiawarenesscontext). |

For the legacy PMv1 path, `MonitorFromWindow` plus `GetDpiForMonitor(MDT_EFFECTIVE_DPI)` in Shcore is available from Windows 8.1 / Server 2012 R2 and appears in Microsoft's older PMv1 sample. Its current reference also cautions against use from per-monitor-aware threads while describing process-aware results. Therefore isolate this as the **legacy initial-DPI compatibility path**, verify it specifically on 10240/1511, and use `GetDpiForWindow` whenever available. Do not make it a universal PMv2 helper. A fallback to system DPI on query failure is degraded behaviour, not proof of correct mixed-monitor scaling. [API caveat](https://learn.microsoft.com/en-us/windows/win32/api/shellscalingapi/nf-shellscalingapi-getdpiformonitor), [Microsoft PMv1 sample](https://github.com/microsoft/Windows-classic-samples/blob/main/Samples/PerMonitorDPIAware/cs/NativeHelpers/PerMonitorDPIHelpers.cpp).

## Save and cancellation semantics

Saving serialises a completed plan snapshot into a uniquely created sibling temporary file, checks the full write and flush, and closes the writer before publication. Existing targets use a same-volume replacement with a recovery backup. A new target uses a same-volume rename without silently overwriting a file that appeared after selection. A changed or competing destination requires a conflict decision, not blind retry. Avoid cross-volume copy/delete as a substitute for the sibling strategy. [Replacement constraints](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew), [move flags](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw).

`ReplaceFileW` can fail after changing names: error 1176 without a backup can remove the original destination; error 1177 can leave the prior file under another name. The contract is to preserve recoverable prior content, inspect the resulting state, retain recovery files on ambiguous failure and report their paths. Never delete them merely because the call returned failure. Keep the in-memory plan and dirty state until the save outcome is established; a successful save of an older snapshot does not mark subsequent edits clean. `REPLACEFILE_WRITE_THROUGH` is unsupported. Neither these APIs nor a flush justify an unconditional guarantee against power loss, faulty storage or a disconnected share. [Documented replacement failures](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew).

Cancellation stops accepting new work, requests cooperative stop, and prevents obsolete results from replacing the current plan. Give work a generation/snapshot identity. Retain job state until completion has been acknowledged, including when a window closes or a completion notification cannot be delivered. Bound queued work and progress notifications. The UI must remain responsive while shutdown drains; avoid waiting on the UI for a worker that synchronously calls back into that UI. Cancelling pending thread-pool callbacks does not stop callbacks already running. [Thread-pool cancellation](https://learn.microsoft.com/en-us/windows/win32/api/threadpoolapiset/nf-threadpoolapiset-waitforthreadpoolworkcallbacks).

For future overlapped I/O, `CancelIoEx` requests cancellation; it does not certify completion. Buffers and `OVERLAPPED` data remain alive until completion, which can still report ordinary success. It is not a universal cancellation function for arbitrary DNS or ICMP handles. [CancelIoEx](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex).

## Required implementation and release evidence

- Inspect the final Release x64 executable's imports and manifest. Confirm `/MT` and absence of application runtime/help sidecars; check libraries for newer imported functions. Verify launch offline as a standard user on clean Windows 10 10240, 1511, 1607 and 1703 images, a representative later Windows 10 build, Windows 11, and Server 2016 Desktop Experience plus later supported Server families. The transitional builds exercise distinct DPI paths.
- Verify first launch on each monitor, 100%/150%/200% scaling, mixed-DPI moves, changing scale, reconnecting Remote Desktop and small work areas. Include calculator, tables, help, About and modal file/print dialogs. Check both real older OSes and forced optional-function absence; a modern OS test alone is insufficient.
- Verify keyboard-only navigation, F1 context, focus after navigation/dialogs, visible focus, high contrast, screen-reader labels and meaningful reading of help tables/images. Confirm no-match search clears stale content and text remains usable without the browser or a printer.
- Verify IPv4/IPv6/CIDR input and malformed suffixes; confirm that typing or pasting a hostname never starts a lookup. Exercise read-only executable locations, Unicode filenames, long-path handling on the oldest baseline, denied writes, sharing locks, disk-full writes, failed replacement, competing writers and disappearing network/removable destinations. Confirm dirty state, previous content/recovery paths and truthful errors.
- Stress rapid edits, cancellation, starting another operation, closing during completion and repeated help/dialog opening. Confirm bounded memory/handles, no stale results, no callbacks into destroyed state and no UI deadlock. Exercise a failed help DLL load and offline external-link failure.

These are acceptance requirements for development after approval. Baseline DPI behaviour, Rich Edit accessibility/images/printing and file-failure recovery remain untested until a real executable exists; this review makes no passing claim.
